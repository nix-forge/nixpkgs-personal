# ArtCraft application packaging research

Reviewed: 2026-10-11. Scope: standalone Crafting Apps, Craft Launcher and the separate ArtCraft studio. The twelve creative app pins retain their October 8 baseline; the newly published launcher is pinned separately. The immutable revisions below are the packaging investigation baseline. This note records source observations, package plans and completed checks. The validation table distinguishes tested platforms from remaining work.

The [upstream-concern review and current validation record](research/artcraft-upstream-review-research.md) follows this initial investigation. Its completed evidence and platform limits supersede the earlier validation status below.

## Answer

The official Storytold organization publishes twelve standalone Crafting Apps. Seven cover Adobe workflows; five add CAD, audio and office workflows. Each has a Rust desktop application and a separate command-line application. PdfCraft is the current PDF application name, while older project documentation calls it PrintCraft. The shared craft-fonts repository is a font/build input, and photocraft-corpus is test data. ArtCraft itself is a separate Tauri studio with a restrictive source-available license. [Official organization inventory](https://api.github.com/orgs/storytold/repos?per_page=100), [PdfCraft README](https://github.com/storytold/pdfcraft/blob/22752dc9157706e55ead60b89a857a9ce03c8fc0/README.md), [ArtCraft license](https://github.com/storytold/artcraft/blob/3e5793b6934b51536606720e5d56bcfd1fe7cc2d/LICENSE.md).

The October 11 inventory also includes Craft Launcher, published after the initial investigation. Include its source-built desktop package and the font package for fourteen outputs. The newer craft-libs repository contains Rust dependencies rather than another standalone application. The repo-status utility and CI actions are development infrastructure outside the Crafting Apps catalog. [Launcher and application catalog](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/README.md), [official repository inventory](https://github.com/orgs/storytold/repositories?type=all).

## Common package plan

The launcher has one desktop executable with a version command, rather than a separate document-processing CLI. Its package plan below preserves this distinction.

Use `rustPlatform.buildRustPackage` with immutable source and Cargo dependency hashes. Cargo.lock must remain authoritative. Build and install only `<app>` and `<app>-cli`; workspace-wide binary installation would also expose release tooling and WebAssembly entry points. Keep declared default features, X11, Wayland and accessibility support. All twelve desktop manifests explicitly enable X11 and Wayland and use eframe/wgpu; these are direct manifest observations, not proof of working displays. The per-package links below identify each manifest.

On Linux, account for winit/eframe's runtime loading of Wayland, X11, xkbcommon and Vulkan/OpenGL libraries. A wrapper must make the required library paths available on NixOS. Use pkg-config and ALSA build inputs for CPAL consumers, specifically FilmCraft, EffectCraft, SoundCraft and DeckCraft. File dialogs and desktop URL/file opening must keep their declared portal/links behavior. Darwin needs SDK/framework support for the declared Rust dependencies; avoid adding Linux libraries there. Test both CPU architectures supported by the repository on Linux and Darwin before claiming those platforms work. Upstream native builds and WebAssembly support are source claims, not substitutes for Nix checks. [PhotoCraft Linux release dependencies](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/.github/workflows/release.yml), [SoundCraft ALSA dependency](https://github.com/storytold/soundcraft/blob/c51e5d5ec52f11c6264b72e26661fa712feb5345/.github/workflows/release.yml), [DeckCraft ALSA dependency](https://github.com/storytold/deckcraft/blob/d0e57d7e25f9852179cc66be12dd6188f1c05535/.github/workflows/release.yml).

Install upstream Linux desktop entries, scalable/raster app icons, MIME definitions and appstream metadata when present. Keep executable names and MIME associations consistent. Build Darwin application bundles with the upstream ICNS icon, Info.plist and document associations when those exist. Set mainProgram to the GUI executable, description to the actual workflow, homepage to the official project, changelog to releases, and sourceProvenance to fromSource. Include only established maintainer identities and restrict platforms to the systems actually supported by the recipe.

Code is MIT OR Apache-2.0 in every standalone workspace. Assets have separate licenses. Install LICENSE-MIT, LICENSE-APACHE, NOTICE and ATTRIBUTION.md, plus the actual licenses for every embedded asset. App icons are distinct from ArtCraft brand marks. Brand assets under docs/brand have a restrictive, revocable license and require removal from distributed modified versions. Several apps embed or redraw those marks in UI code. Packaging must either preserve an applicable upstream permission and report its restrictive license, or remove the marks completely, including rendered code paths. Merely deleting documentation does not remove compiled marks. [PhotoCraft asset inventory](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/ATTRIBUTION.md), [brand conditions](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/docs/brand/LICENSE-brand.txt), [PdfCraft embedded marks](https://github.com/storytold/pdfcraft/blob/22752dc9157706e55ead60b89a857a9ce03c8fc0/crates/ui-egui/src/widgets.rs), [DesignCraft drawn mark](https://github.com/storytold/designcraft/blob/14e677b24216396e398823ff034d9882322362d1/crates/ui-egui/src/about.rs).

## Launcher package plan

Build the `artcraft-launcher` Rust desktop crate as `craft-launcher`, preserving WGPU, accessibility, native tray, persistence, links and X11/Wayland. Do not enable the developer local-mirror feature. Run offline workspace library and native binary tests, excluding WASM and xtask. Synthetic HTTP/instance tests need loopback permission on Darwin; Linux process tests need native procps and sandbox-compatible sleep/touch commands. [Desktop manifest](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/apps/artcraft-launcher/Cargo.toml), [native backend](https://github.com/storytold/craft-launcher/tree/6e7a122866591c067344687c45c92f735a1d189b/crates/native/src).

The modified build must be called Craft Launcher and remove restricted graphical marks, including tray and window icons. Generate an original neutral icon from package-local SVG source, retain permissive application/social/font assets and notices, and supply signed Darwin bundles and Linux desktop/AppStream metadata. Pin Noto Sans CJK SC from the reviewed craft-fonts input for Chinese UI; retain upstream platform fallbacks. [Brand conditions](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/docs/brand/LICENSE-brand.txt), [asset attribution](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/ATTRIBUTION.md), [Chinese font loading](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/crates/ui-egui/src/cjk_font.rs).

Nix integration detects canonical store-backed profile executables and macOS application bundles before unmanaged copies or stale manifest entries. It opens Nix-managed apps, refuses updates/removal before downloads or file changes, and disables its own store-backed self-update. Other installations retain upstream management. Linux downloaded AppImages and generated desktop entries use appimage-run; autostart uses the installed wrapper. Regressions cover coexistence, store boundaries, ownership, desktop quoting, wrapper paths and Chinese font availability. These are packaging changes inferred from the upstream ownership and process code. [Discovery](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/crates/native/src/detect.rs), [installation](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/crates/native/src/install.rs), [autostart](https://github.com/storytold/craft-launcher/blob/6e7a122866591c067344687c45c92f735a1d189b/crates/native/src/login.rs).

The launcher sets `C.UTF-8` only for Linux pgrep subprocesses: the C locale fails its original Unicode-path matching assertion. A regression verifies that other helper processes keep their locale. Darwin retains its process behavior. Five Darwin service tests require Apple signing/disk-image tools or process inspection unavailable in the Nix sandbox; they remain in a separate source-built native test artifact and pass outside the sandbox using temporary bundles. No host policy is changed.

Darwin rasterizes the original neutral, font-free SVG with resvg. A Nixpkgs 26.05 HarfBuzz CoreText fixture failure blocked librsvg's Pango dependency during Intel validation; choosing another build-time renderer avoids that dependency without disabling its tests. Linux retains librsvg and its exact previously validated derivation. [resvg command-line implementation](https://github.com/linebender/resvg/blob/v0.48.1/crates/resvg/src/main.rs).

## Shared font input

Pin `storytold/craft-fonts` at `8dcdacd5153e64560d109541a47d806f26f048c0` (committed 2026-10-06). Set `CRAFT_FONTS_DIR` to its absolute store source path and `CRAFT_FONTS_REQUIRED=1` for apps whose build scripts support it. The build scripts parse `fonts/manifest.txt`, canonicalize font paths and compile font bytes into the binary. No runtime sibling checkout is needed. The input currently contains Japanese BIZ UDPGothic, Shippori Mincho and BIZ UDMincho, Simplified Chinese Noto Sans CJK SC and variable Noto Sans Arabic. Fonts are OFL-1.1; install each family's OFL.txt and ATTRIBUTION.md with the consuming application's notices. Its Rust library is MIT OR Apache-2.0, separate from the font licenses. [Font README](https://github.com/storytold/craft-fonts/blob/8dcdacd5153e64560d109541a47d806f26f048c0/README.md), [font attribution and reserved names](https://github.com/storytold/craft-fonts/blob/8dcdacd5153e64560d109541a47d806f26f048c0/ATTRIBUTION.md), [PhotoCraft embedding script](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/crates/text/build.rs).

## Per-package decisions and checks

### photocraft

Build packages `photocraft` and `photocraft-cli`. Enable `heif` for the desktop and CLI. The implementation uses the pure-Rust `photocraft-heif`/heic-rs stack; it does not require libheif. Preserve the CC BY 3.0 attribution for the magnetic-lasso glyph, the SCOWL wordlist notice, Lucide/Feather ISC/MIT notices, OFL font notices and CC0 ICC-profile attribution. Check default workspace tests with HEIF enabled. External PSD/HEIF corpora belong in a separately pinned test input; do not enable `corpus` without supplying them. GPU parity tests need a usable GPU or documented software adapter. The ignored large-PSB test allocates about 12 GB and should remain excluded from ordinary builds. [Workspace manifest](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/Cargo.toml), [desktop manifest](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/apps/photocraft/Cargo.toml), [CLI manifest](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/apps/photocraft-cli/Cargo.toml), [asset inventory](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/ATTRIBUTION.md), [release workflow](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/.github/workflows/release.yml).

PhotoCraft's pinned text engine embeds every manifest entry but registers only Japanese fonts, contradicting its existing all-family regression and omitting Chinese and Arabic from runtime text. The package patches registration to include every embedded font. Its test environment sets `PHOTOCRAFT_LOCALE=ja` because a separate Japanese fallback test assumes Japanese preference; runtime locale selection is unchanged. [Registration](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/crates/text/src/fonts.rs), [existing regressions](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/crates/text/src/tests.rs), [locale preference](https://github.com/storytold/photocraft/blob/e5e3e397523b4db6a016dd19526e4c68514fcc72/crates/text/src/cjk.rs).

### filmcraft

Build packages `filmcraft` and `filmcraft-cli`. Offer and test the `whisper` feature, which enables pure-Rust Candle inference and the separate speech-download feature. Model downloads happen at runtime; do not download model weights in sandboxed compilation or tests. CPAL needs ALSA on Linux. FilmCraft implements its own codecs; FFmpeg is an external test oracle, not a runtime dependency. Add FFmpeg only to test inputs when running codec suites. `FILMCRAFT_REQUIRE_ORACLES=1` makes missing external oracle checks fail rather than skip. Include craft-fonts and CLI media/probe/render checks; do not claim speech accuracy without model-backed tests. ## Separate ArtCraft studio

At `3e5793b6934b51536606720e5d56bcfd1fe7cc2d`, the studio is a Tauri 2 Rust desktop application backed by an npm workspace with React, Nx and Vite. Tauri config reports application version 0.41.0, but the Rust desktop package manifest still reports 0.0.1, so deriving the product version from Cargo alone is wrong. The frontend lives in frontend/, its output is frontend/apps/artcraft/dist, and the Tauri build hook invokes `npx nx run artcraft:build`. A source recipe must pin npm dependencies, run Nx offline with its daemon disabled, vendor the Cargo workspace, build the frontend first, and avoid a network-dependent npx invocation during Cargo build. Linux requires the Tauri GTK/WebKit stack; Darwin needs the platform webview and application bundle. These are packaging inferences from the manifests and config. [Frontend manifest](https://github.com/storytold/artcraft/blob/3e5793b6934b51536606720e5d56bcfd1fe7cc2d/frontend/package.json), [desktop manifest](https://github.com/storytold/artcraft/blob/3e5793b6934b51536606720e5d56bcfd1fe7cc2d/crates/desktop/artcraft/Cargo.toml), [Tauri config](https://github.com/storytold/artcraft/blob/3e5793b6934b51536606720e5d56bcfd1fe7cc2d/crates/desktop/artcraft/tauri.conf.json).

The root license permits personal compilation and use but restricts competition, commercial software sales and removal of community/payment links. It is not an OSI open-source license. A studio package would need explicit unfree metadata, separate license handling and a clearer redistribution basis; do not apply the standalone apps' MIT/Apache metadata to it. The React package.json MIT field does not override the root license. Network model/provider access and account integrations also mean an offline GUI launch cannot validate its principal generation workflows. ## Local compatibility corrections

FilmCraft’s three buffer-recycling tests share a global reuse counter. A test-only mutex isolates their counter and buffer assertions from parallel test execution; production pooling and every original assertion remain unchanged.

Native library tests use the upstream development/test profiles with debug assertions enabled. The check phase disables incremental compilation and disposable debug symbols because Nix does not reuse those artifacts; this also keeps the test build within temporary-disk limits on native Linux builders. Release profiles and installed binaries retain upstream optimization settings.

VectorCraft, WordCraft and DesignCraft also register only the Japanese subset in their document font databases. Their patches append the remaining manifest fonts after the existing sorted Japanese fallback list and add full-family registration assertions without system fonts. DesignCraft's historical fallback fixtures retain their Japanese-only preconditions locally; the full-manifest regression uses the ordinary database. Its no-tatweel justification fixture uses an explicit synthetic font because the newly available Arabic font supports tatweel. Its isolated Arabic assertion compares each complete ordered glyph cluster with standalone shaping, accounting for the font's GSUB substitution into multiple glyphs instead of assuming a single raw cmap glyph. [Vector registration](https://github.com/storytold/vectorcraft/blob/c0396c0761f7e58778ba21bb249a8a6f23db99a3/crates/text/src/fontdb.rs), [Word registration](https://github.com/storytold/wordcraft/blob/7584b9b2930ffddfe7db96b6eba977262e55135c/crates/fonts/src/fontdb.rs), [Design registration and fallback fixtures](https://github.com/storytold/designcraft/tree/14e677b24216396e398823ff034d9882322362d1/crates/fonts/src).

FilmCraft and EffectCraft's macOS font-directory tests assume more than twenty host fonts and Helvetica, which are unavailable in a pure build sandbox. Darwin-only test patches retain the one-time system-scan assertion and use the bundled Inter Bold file for directory discovery, lazy loading and glyph lookup. Runtime font scanning is unchanged. [Font source and regression](https://github.com/storytold/filmcraft/blob/5231852443363f001c3f6b396dd9b1e6461ae2be/crates/text/src/fonts.rs), [EffectCraft font source and regression](https://github.com/storytold/effectcraft/blob/d60cb71e297a4bb76851b27b48c0014b56ccab69/crates/text/src/fonts.rs).

LightCraft's Candle 0.9.2 dependency selects a Metal device without checking that the requested device exists. In a macOS sandbox with no visible GPU, this panics before model validation and defeats LightCraft's documented CPU fallback. A Darwin-only vendor patch returns an error for an unavailable ordinal, allowing the existing fallback; the missing/corrupt-model tests remain enabled. The vendor checksum is updated for the modified file while the immutable Cargo input remains pinned. [Candle source corresponding to its published crate](https://github.com/huggingface/candle/blob/3b39794c14b1de8ba4c2d10d49354d557a415547/candle-core/src/metal_backend/mod.rs), [LightCraft device selection](https://github.com/storytold/lightcraft/blob/2472021091a28eb93a05947cfc9b941d3911543a/crates/segment/src/lib.rs).

EffectCraft's ARM Linux debug test reports an overflow in the integer multiplication used for temporal neighbour sampling. The frame count is clamped to 240 and the direction is either -1 or 1, so the report does not establish overflowing input values. The local correction converts both factors to floating-point time before multiplying. These bounded integer offsets remain exactly representable, preserving sample times. The original smoothing test stays enabled, and a new host-request regression checks zero, two-frame and clamped 240-frame windows in both directions. [Temporal sampling and upstream regression](https://github.com/storytold/effectcraft/blob/d60cb71e297a4bb76851b27b48c0014b56ccab69/crates/effects/src/color2.rs).

FilmCraft's 24-track mixer benchmark measures thread CPU time and requires faster-than-real-time mixing. ARM Linux execution through QEMU ran the full workload but failed this native CPU threshold. An ARM Linux-only test patch retains the workload and timing report, then checks both channels for the requested sample count, finite samples and audible output. Only that package's check phase selects output verification instead of the speed gate. The original real-time assertion remains the default outside this mode and on the other packaged platforms. This validates mixer output under emulation; it does not establish native ARM playback performance. [Mixer benchmark and output tests](https://github.com/storytold/filmcraft/blob/5231852443363f001c3f6b396dd9b1e6461ae2be/crates/render/src/mixer_tests.rs).

## Validation and limits

The public flake exports Linux on both architectures and ARM Darwin. Intel Darwin requires an independent recipe with a supported Nixpkgs 26.05 package set and Rust 1.95 or newer; the compatible Nixpkgs 26.05 pin `c5c4a43b0e8056328ec4529f735cabdb8f1942bb` meets that requirement. The standalone project’s Nixpkgs 26.11 pin has dropped Intel Darwin support, so its public flake and overlay do not expose that system. Recipe metadata includes Intel Darwin for use with a compatible caller. [Nixpkgs 26.05 Intel Darwin support policy](https://nixos.org/manual/nixpkgs/unstable/release-notes#sec-release-26.05).

The following table covers thirteen desktop applications, including Craft Launcher, and the separate font package. The completed results below distinguish native execution, QEMU execution and cross compilation.

The investigation retrieved the official organization inventory, immutable source trees, Cargo manifests, release workflows and asset inventories. Implementation added twelve source-built desktop/CLI applications, Craft Launcher and a separate font package. Creative-app checks run workspace library tests with default application features, installed CLI document/media exports and GUI startup. Launcher checks also include native binary tests, its version command and packaging regressions. Browser/WASM, developer xtask, creative-app binary/integration targets, external corpora, hardware-dependent workflows and optional downloaded models remain outside the offline suite. PdfCraft includes pinned OCR models and model-backed library regressions. PhotoCraft enables HEIF and FilmCraft enables Whisper in both installed executables.
