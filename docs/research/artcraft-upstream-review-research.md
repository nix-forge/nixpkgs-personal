# Crafting Apps package review: upstream concerns and Nixpkgs conventions

Research snapshots were collected and reviewed on 2026-10-11 and 2026-10-12. Implementation review and validation continued on 2026-10-14. Question: which upstream reports and competing Nix recipes justify changes to the fifteen independently packaged Crafting Apps outputs, while preserving source reproducibility and truthful platform claims?

The initial [packaging investigation](../artcraft-packaging-research.md) records the source pins and original package plans. This follow-up reviews upstream concerns and the resulting changes.

## Earlier implementation findings

### Answer at the original pins

Keep the current immutable application pins and improve the package mechanisms supported by the evidence: Linux D-Bus loading and fontconfig commands, desktop identity, compound code/asset licensing, stable-compatible Darwin metadata, standard font installation, approved DeckCraft default fonts, complete embedded-font notices and PdfCraft's permitted Chinese and Thai fallbacks. Carry narrowly scoped WordCraft, launcher and Intel PhotoCraft source fixes with their upstream regressions. Preserve GUI plus CLI installation, scoped source tests, font/model attribution, and post-fixup Darwin signing.

Application-format fidelity, missing native tablet/file-drop protocols, rendering correctness and data migrations remain upstream work. Neither adding libraries nor successfully opening a window establishes those features. LightCraft's current pin has no HEIF decoder; its accepted implementation requires a substantial reviewed source upgrade. The current winit stack already supplies basic fallback Wayland decorations, so Adwaita is not necessary merely to obtain window controls.
