# Packaging REA and its agent skill

Reviewed: 2026-10-13. Scope: REA 6.4.0, release tag `rea-agents-6.4.0`, commit `a56f7bb668ab23fec8d33f7af353ac7ed2fe1895`.

## Answer

Build the stable CLI and MCP server from their tagged TypeScript source with Nixpkgs `buildNpmPackage`. Keep its generated workflow skill in the runtime package, and expose that same generated bundle in a separate `skills` output for declarative agent configuration. Compile the matching native PTY addon from source instead of retaining its npm prebuilt binary. Optional analysis providers remain explicitly selected external tools.

## Findings and sources

### Release, build, and metadata

The [latest stable GitHub release](https://github.com/morluto/rea/releases/tag/rea-agents-6.4.0) and [npm metadata](https://registry.npmjs.org/rea-agents/6.4.0) identify version 6.4.0. Its npm `gitHead` matches the release commit. Repository main has already advanced while retaining the same package version: a version string alone cannot identify source bytes. Use the release tag and a fixed source hash. The upstream [release-boundary guide](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/docs/installation.md#released-package-and-main) explicitly distinguishes development source from published releases.

The release [package manifest](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/package.json) names the npm package `rea-agents`, exports both `rea` and `rea-agents` launchers, and requires Node `^22.19.0 || ^24.11.0 || >=26.0.0`. Its `build` script invokes Turbo's skill artifact task; the [task graph](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/turbo.json) compiles TypeScript first. A maintained Node 24 runtime satisfying the declared range is a suitable packaging choice; this is a packaging recommendation, not an upstream requirement to use one particular major.

The stable release has no optional Frida dependency, no `bundle-runtime.mjs`, and no `THIRD_PARTY_NOTICES.md`. Those files and dependencies seen on newer main must not be assumed to exist at this pin. The release ships a [MIT license](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/LICENSE), bridge scripts, selected third-party notices, and the original license files selected by the manifest. Preserve these using upstream's npm packing inventory. `meta.mainProgram = "rea"`, a concise description, the official homepage, and `lib.licenses.mit` accurately describe the CLI. This software is a terminal/MCP service; it supplies no desktop entry or macOS application bundle to justify synthetic desktop or plist metadata.

[Nixpkgs documents `buildNpmPackage`](https://nixos.org/manual/nixpkgs/unstable/#javascript-buildNpmPackage) as a reproducible npm-cache builder. Its default installation follows the upstream package packing inventory and creates the manifest's executable wrappers. Use a fixed `npmDepsHash`, keep the lockfile, and set `npmPackFlags = [ "--ignore-scripts" ]` to prevent the prepack lifecycle from rebuilding during installation. Native build tools belong in `nativeBuildInputs`; host libraries belong in `buildInputs`.

The upstream [prepare lifecycle](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/scripts/prepare.mjs) installs Husky hooks in development source trees unless `HUSKY=0`. Set that variable in the derivation. The [dependency verifier](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/scripts/check-dependency-install.mjs) compares direct development and runtime dependencies against npm's hidden installed lockfile; building with development dependencies omitted will fail by design. Prune development dependencies after building, using the normal builder installation hook.

### Native PTY dependency

REA depends on `@lydell/node-pty` 1.1.0. Its [locked optional platform packages](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/package-lock.json) provide native binaries for Linux and Darwin on x86-64 and ARM64. The loader selects the platform package at runtime; omitting all npm optional dependencies disables this feature. The wrapper npm tarball contains no native build source.

The matching source is the historical [lydell/node-pty v1.1.0 tag](https://github.com/lydell/node-pty/tree/v1.1.0), an annotated tag resolving to commit `0407346d07b22729198c26d564011d96fca33297`. Its [manifest](https://github.com/lydell/node-pty/blob/0407346d07b22729198c26d564011d96fca33297/package.json) records `forkVersion: 1.1.0`, upstream base `1.1.0-beta14`, and `node-addon-api` as the native header dependency. Current microsoft/node-pty v1.1.0 belongs to a different lineage and should not replace this source silently.

The fork's [binding.gyp](https://github.com/lydell/node-pty/blob/0407346d07b22729198c26d564011d96fca33297/binding.gyp) builds `pty.node` from `src/unix/pty.cc` through the Node-API C++ headers, linking `libutil` on Linux. On Darwin it additionally builds the executable `spawn-helper` from `src/unix/spawn-helper.cc`. Its [distribution script](https://github.com/lydell/node-pty/blob/0407346d07b22729198c26d564011d96fca33297/scripts/build-sub-package.js) places these files directly in the platform-specific npm package. Build against local Nix Node headers, then replace the corresponding npm binaries at those paths before packaging. Preserve executable permissions on Darwin's helper. Pin this independent source and its header dependency and verify the fork version against the REA lockfile during builds or updates.

Local inspection of the shipped Linux x86-64 binary found dependencies on `libstdc++`, `libgcc`, and glibc. Building the replacement natively avoids an unnecessary prebuilt-binary patching step. Advertise only supported Linux/Darwin x86-64 and ARM64 platforms until broader platform behavior is established.

### Skills and setup

The authored [reverse-engineer-anything skill](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/.agents/skills/reverse-engineer-anything/SKILL.md) is MIT-licensed project content with six reference files. Its own skill revision is distinct from the application version. The [skill generator](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/scripts/generate-skill-metadata.mjs) copies the full authored directory into `skills/reverse-engineer-anything`, injects the compiled MCP tool count, and replaces unpinned fallback npm invocations with the release-specific package reference. Ship the generated directory unchanged; do not hardcode its version or tool count in Nix.

The [setup skill installer](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/src/application/SetupSkill.ts) reads the generated files through URLs relative to compiled application modules. Removing them from the runtime package breaks the user-invoked setup operation. Keep that package-relative path valid, either with the original files or a symlink to the `skills` output. The separate output can contain only `share/agent-skills/reverse-engineer-anything` and licensing, allowing agents to consume data without retaining the Node runtime closure. Its release and generation remain tied to the CLI's source and dependency pins. A second independent source-only package would miss generated metadata or introduce a second release pin that can drift.

Upstream's [skill-only installation guide](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/docs/installation.md#skill-only-installation) states that skill installation supplies instructions and references, not MCP registration or analysis engines. Preserve that separation: installing the Nix package or skill output must not write agent configuration. Document a declarative file mapping for consumers and a direct MCP command using the packaged `rea mcp` executable. The [setup host](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/src/application/SetupHost.ts) already selects the directly invoked CLI path when not running through npm exec. User-invoked setup can therefore register the immutable Nix executable if the executable wrappers and shebangs are correct.

The [target requirements](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/README.md#what-you-can-analyze) distinguish built-in static JavaScript/.NET/package inspection from caller-supplied native engines, browsers, Android tools, and firmware tools. Do not pull every optional provider or commercial engine into the default runtime. Verify built-in behavior with no such providers present.

The [EVMole integration profile](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/third_party/evmole/README.md) explicitly uses the unchanged locked npm distribution, including its WASM engine. REA retains the engine's MIT notice because that npm tarball omits it. Record this precompiled dependency as `binaryBytecode` alongside REA's own source provenance. The native addon also compiles inline Node-API header code; preserve the [header dependency's MIT license](https://github.com/nodejs/node-addon-api/blob/v7.1.0/LICENSE.md) in the installed runtime.

### Updates and tests

[`nix-update`](https://github.com/Mic92/nix-update#usage) supports both source hashes and `buildNpmPackage` dependency hashes, non-Nixpkgs flakes, and release prefixes through `--version-regex 'rea-agents-(.*)'`. This package also has an independently fetched native fork and its locked header dependency. Its package-local updater follows the repository's transactional updater contract to refresh these inputs together, checks that the registry and release commit agree, and stops for newly added optional runtime dependencies. It preserves both upstream dependency locks rather than generating new resolutions.

Recommended package checks exercise both launchers, a static analysis fixture, MCP initialization/catalog behavior, PTY spawn and exit, complete generated skill references, and user-scoped setup dry-run under an isolated temporary home. PTY and setup checks are essential because a CLI version check alone misses native-library and package-relative resource failures. Upstream has appropriate [process capture capability checks](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/src/process/capture/ProcessCaptureCapability.ts), [skill filesystem tests](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/tests/boundary/filesystem/generatedSkill.test.ts), and MCP boundary tests to select or adapt.

## Validation and limits

Research inspected the pinned upstream sources, GitHub release/tag metadata, npm metadata and tarball contents, the native dependency source tag, and the shipped Linux ELF dependency list. No package build, agent installation, user configuration change, or external-engine test ran during this research. Native Linux, Darwin, and cross-build behavior require implementation validation; platform-specific provider capability remains bounded by upstream's documented requirements.

Implementation validation subsequently passed native x86-64 Linux and ARM64 Darwin builds, each with 1,706 upstream domain tests and three skipped. Install checks passed both CLI aliases, native PTY spawning, MCP initialization and tool enumeration, generated skill resources, and isolated setup preview. Static JavaScript analysis passed on Linux and outside Darwin's Nix sandbox. Inside the Darwin sandbox, that operation is omitted because process visibility prevents the worker ownership check from completing; the package preserves that ownership check. The independent `skills` output's recursive store closure contains only itself.

The real updater's no-write preview reproduced every committed 6.4.0 pin. Eight updater tests cover release identity, dependency pin refresh, changed licensing, failure preservation and preview behavior. All exported flake systems evaluated successfully. Repository source-pin, updater-command, updater-unit, application-metadata, package-independence, package-policy, template and helper checks passed on native Darwin, as did Python formatting/lint/type checks, TypeScript, Oxlint and scoped repository hooks. Python formatting/lint/type checks and the eight updater tests also passed on Linux. CLI version tests passed on both native platforms. The ARM64 Linux addon cross build passed, and ELF inspection identified an AArch64 module. Native ARM Linux runtime tests need an ARM worker. No optional engine or interactive GUI check was run.

## Darwin helper follow-up

The [Darwin process token reader](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/src/process/DarwinProcessRunTokenReader.ts) has no environment-based executable override. It compiles its two Swift sources into a new temporary directory for each REA process; only the Swift module cache is reused. Its `xcrun` option changes the compiler launcher for injected tests. Core worker process ownership calls this helper, so static JavaScript inspection can require the compiler even without a native-analysis provider.

Precompile [ProcessRunTokenReader.swift](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/bridge/process/ProcessRunTokenReader.swift) and [ProcessRunTokenReaderMain.swift](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/bridge/process/ProcessRunTokenReaderMain.swift) using the Nix Swift compiler and SDK. Their imports are Foundation and Darwin. Install an executable `bridge/process/rea-process-token-reader` in the npm package directory. A narrow source patch can initialize the existing cached `executable` variable to `fileURLToPath(new URL("../../bridge/process/rea-process-token-reader", import.meta.url))` when `options.xcrun` is absent, keeping the original compiler path when tests explicitly inject that option. Existing `compile()` checks closed state and cancellation before returning the executable. Because no temporary root is allocated, cleanup cannot delete or change the installed binary.

The second runtime compiler is [NativeUiHelperRuntime.ts](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/src/native/NativeUiHelperRuntime.ts). Precompile [NativeUIChildren.swift](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/bridge/native/NativeUIChildren.swift) together with [ReaNativeUI.swift](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/bridge/native/ReaNativeUI.swift), naming or symlinking the latter `main.swift` as upstream does for its top-level entry code. Imports require AppKit, ApplicationServices, CryptoKit, ScreenCaptureKit, and Darwin. A macOS 14 or later SDK exposes the screenshot APIs; runtime screenshot requests retain upstream's macOS 14 availability guard and permission checks. Initialize that runtime's cached executable to the packaged `bridge/native/rea-native-ui` path. Preserve execution environment, interruption, timeouts, output parsing, and ownership checks. Both binaries must be installed explicitly because their names are absent from the release manifest's npm file inventory.

[CommandRunner.ts](https://github.com/morluto/rea/blob/a56f7bb668ab23fec8d33f7af353ac7ed2fe1895/src/native/CommandRunner.ts) separately resolves optional Apple inspection tools through `xcrun --find`, including codesign, dwarfdump, nm, otool, swift-demangle, and related tools. Precompiling REA's own helpers does not supply those external analysis tools. Actual sysctl visibility, accessibility and screenshot authorization remain host-dependent and must still be validated; avoiding runtime compilation must not bypass those checks.
